## Our SciPy paper is out

**ArcadeDB in Python: An In-Process Multi-Model Database** is in the [SciPy Proceedings](https://proceedings.scipy.org/articles/fwvt2525), DOI `10.25080/fwvt2525`. The [research page](/research/arcadedb-python) has the method, the benchmark tables and the BibTeX entry.

## What it covers

Some Python programs need transactions over documents, graph traversals and vector search at once. Usually that means three systems, each with its own copy of the data, and application code to keep the copies in sync.

The package runs ArcadeDB inside the Python process instead, so one database does all three. You query documents with SQL, the graph with openCypher, and vectors through an HNSW-family index. The wheel bundles a Java runtime, so you do not need Java installed. From the 26.11.1 release the package is named `arcadedb`. The paper uses its current name, `arcadedb-embedded`.

We show a workflow that chains a vector search, a SQL filter and a graph traversal over one dataset. We also benchmark the package against SQLite, DuckDB, LadybugDB and Chroma on a Q&A corpus. Each specialist wins on its own model. ArcadeDB is competitive on all three, and the cost is memory and loading time.
